Agents talk. The broker keeps them honest.

agentbus gives AI agents inboxes, shared task queues and broadcast events over MQTT. Every message passes a broker that checks who sent it, who may receive it, and whether it is still worth delivering. Small agents built on it can hand their messages to a model.

01 · how it talks

      
Three ways to send a message

      
Every payload is one JSON envelope on one of four topic shapes under a2a/v1/. Pick the shape by who should get it.

    

    

      

        
        
Inbox: request and reply

        
Send to one agent by name. A request carries a TTL and gets exactly one reply or error, matched by correlation_id.

        a2a/v1/agents/{id}/inbox
      

      

        
        
Task queue: one of many workers

        
Send to a capability, not an agent. A shared subscription hands each task to exactly one worker, so adding workers spreads the load.

        a2a/v1/tasks/{capability}
      

      

        
        
Events: broadcast

        
Publish under your own name; anyone may subscribe with wildcards. No replies, no routing decisions, just a record that something happened.

        a2a/v1/events/{id}/{name...}
      

    

    

      

        
One envelope for all of it

        
Inbox, task and event payloads share one JSON shape. The broker parses it, checks from against the connection, checks to against the topic, drops it if ts + ttl_ms has passed, and re-encodes it before delivery.

        The envelope, field by field →
      

      
{
  "v": 1,
  "id": "6f1c0e9a2b7d4c3e8a9b0c1d2e3f4a5b",
  "type": "request",
  "from": "claude-code",
  "to": "weather",
  "ts": "2026-11-15T16:04:05.123Z",
  "ttl_ms": 60000,
  "capability": "weather.forecast",
  "body": {"location": "Seattle, WA", "days": 2}
}

    

  


  
  

    

      
02 · the broker says no

      
Every publish is checked

      
mochi-mqtt does the protocol work. One agentbus hook turns it into a broker that knows about agents: each has a token, a list of who it may message, and the task queues it may serve. A refused message gets an error envelope back, so a pending request fails at once instead of timing out.

    

    

      
not_authorized
Writing to a topic you don't own, or to an inbox outside send_to.

      
invalid
Malformed envelope, a forged from, a to that doesn't match the topic, a stale ts.

      
rate_limited
Over the per-agent rate: 20 a second, burst 50, unless configured.

      
expired
ts + ttl_ms has passed. Nobody wants yesterday's request.

      
too_large
Over max_envelope_bytes, 256 KiB by default.

      
no_route
The recipient isn't configured, or is offline with nowhere to queue.

      
no_consumer
Nobody serves the task's capability.

      
queue_full
The recipient has been away a while and its queue is at max_queued.

04 · agents that think

      
A model decides. Your scripts do the work.

      
Give a standalone agent an llm: handler and a model answers its messages. It decides what to check, calls the agent's own scripts and Go functions as tools, asks other agents on the bus when it needs to, and replies. Use Claude, or any OpenAI-compatible server, local models included. It's still one binary, and the API key comes from each host.

    

    

      

        
        
requesttool callreply

      

      
agent: hostdoc
llm: {provider: anthropic, model: claude-haiku-5-5}
handlers:
  - task: hostdoc.ask
    timeout: 120s
    llm:
      system: |
        You look after this host. Check with the
        tools before you answer; never guess.
      tools: [disk, top]           # handlers below
      bus: {task: [weather.forecast]}
      reply: json
  - name: disk                     # no trigger: a tool
    run: df -Ph
  - name: top
    script: scripts/top.py
    params: {type: object, properties: {limit: {type: integer}}}

    

    

      

        
Tools are your handlers

        
A handler with no trigger runs only when the model calls it. Each call runs as a request from the original sender, so the tool's allow_from still holds. Commands never see the model key.

        tools: [disk, top]
      

      

        
The bus, within limits

        
The model can reach only the agents and capabilities you list, and the broker's grants still apply on top. Each call carries a hops count, so agents asking agents stop at max_hops.

        bus: {task: [weather.forecast]}
      

      

        
Any model

        
Anthropic, or anything that speaks the OpenAI API: OpenRouter, Ollama, vLLM, llama.cpp, LM Studio. Point base_url at a local server and no key is needed. The standard library is the only dependency.

        provider: openai

A sender can't change it

        
The model, prompt, tools and bus permissions come from the manifest. The message reaches the model marked as untrusted input. When something fails, the requester gets a code such as model_gave_up or bad_model_output, and API errors stay in the agent's log.

        
A message can still talk the model into calling the tools you gave it, so keep tools read-only and check their input.

05 · bring any agent

      
Go, Python, a shell script, or Claude

      
CONTRACT.md is language-neutral: any MQTT client that follows it can join. These are ready-made.

    

    

      

        
        
        
        
        
      

      

        
c, err := client.Connect(ctx, client.Options{
    BrokerURL: url, AgentID: "counter", Token: tok,
    Description: `wordcount: body {"text": string}, replies {"words": int}.`,
    Tasks:       map[string]client.Handler{"wordcount": wordcount},
})

// A handler's return value is the reply body.
func wordcount(ctx context.Context, e *a2a.Envelope) (any, error) {
    var b struct{ Text string `json:"text"` }
    if err := e.DecodeBody(&b); err != nil {
        return nil, client.Errorf("invalid", `body must be {"text": "..."}`)
    }
    return map[string]int{"words": len(strings.Fields(b.Text))}, nil
}

        
The Go client, on paho over MQTT 3.1.1. Writing a service agent →

      

      

        
from agentbus import Agent, ReplyError

def summarize(env):
    body = env.get("body")
    if not isinstance(body, dict) or "text" not in body:
        raise ReplyError("invalid", 'body must be {"text": "..."}')  # the caller sees this
    return {"summary": body["text"][:100]}                          # the reply body

agent = Agent.from_env(
    "summarizer",
    description='summarize: body {"text": string}, replies {"summary": string}',
    tasks={"summarize": summarize},
    max_concurrent=2,
)
with agent:
    reply = agent.request("researcher", {"q": "..."}, timeout=120)

        
One file on paho-mqtt. The Python example →

      

      

        
agentbus config agent add weather --capability weather.forecast   # prints where its token is

# answer every weather.forecast task with a script
agentbus --agent weather handle --capability weather.forecast --exec ./forecast.sh

# from anywhere else on the bus
agentbus task -c weather.forecast --body '{"location":"Seattle, WA","days":2}'
agentbus request --to weather --body '{"op":"ping"}'
agentbus emit --name jobs/done --body '{"id":42}'

        
The CLI is a client too: handle runs a command per message, envelope on stdin, reply on stdout. The CLI →

      

      

        
agent: disk-agent                       # agent ID; AGENTBUS_AGENT overrides
description: Disk usage on build hosts  # starts the presence description
max_concurrent: 4                       # handlers at once; beyond that, "busy"
timeout: 60s                            # default per handler
drain: 30s                              # on SIGTERM, time for running handlers
allow_from: [ops, conduit-home]         # default sender allow-list; all if unset
handlers:
  - task: disk.usage                    # trigger
    script: scripts/disk.sh             # action
    timeout: 10s
